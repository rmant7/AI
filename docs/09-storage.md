# 9. Хранение на устройстве

## Раскладка

```
/app
   исполняемое приложение

/models
   /text
   /audio
   /vision
   /video
   /embedding

/data
   /conversations      SQLite
   /memory             факты, предпочтения, сущности
   /documents          исходники загруженных файлов
   /embeddings         векторный индекс

/cache
   промежуточные кадры, распакованные архивы, временные аудио-чанки

/config
   настройки, профиль устройства, зафиксированные предпочтения

/pipelines
   пользовательские графы (JSON)
```

Модель — это просто файл или набор файлов. Приложение знает о ней ровно то, что
записано в реестре:

```
model_id
runtime
capabilities
requirements   (RAM, storage, API level, ускорители)
location
```

## Что где лежит

| Данные | Хранилище | Почему |
|---|---|---|
| conversations, messages | SQLite | нужны транзакции, сортировка, полнотекстовый поиск |
| каталог моделей, статусы загрузок | SQLite | точность важнее гибкости |
| настройки, профиль устройства | SQLite / config | читается при старте |
| пайплайны | JSON в `/pipelines` + индекс в SQLite | пользователь должен уметь экспортировать и передать |
| факты и предпочтения | memory store | вероятностные данные, отдельный жизненный цикл |
| документы и чанки | vector store + `/documents` | переиндексация не должна трогать оригиналы |

Разделение — то же, что в [05-memory-knowledge.md](05-memory-knowledge.md):
приложение, память, знания.

## Правила для файлов моделей

1. Артефакты моделей никогда не пишутся в каталог, который система может
   очистить как кэш. Потеря 5 ГБ, скачанных по мобильной сети, — это отказ, а не
   освобождение места.
2. `/cache` — наоборот, полностью одноразовый: любой файл там должен
   восстанавливаться пересчётом.
3. Удаление модели удаляет её артефакты и **не трогает** ни память, ни индексы
   знаний. Единственное исключение — удаление embedding-модели, после которого
   индекс необходимо переиндексировать; поэтому такое удаление должно явно
   предупреждать пользователя (см. [02-capabilities.md](02-capabilities.md)).
4. Свободное место проверяется до старта загрузки и повторно перед распаковкой:
   `NOT_ENOUGH_STORAGE` в скорере отсекает заведомо невозможное, но состояние
   диска меняется между показом списка и нажатием «скачать».

## Рост объёма

Основной источник неконтролируемого роста — не память и не документы, а сами
модели. Отсюда правило из [03-model-registry.md](03-model-registry.md):
каталог обновляется автоматически, модели — только по явному действию
пользователя. Второй источник — кадры видео в `/cache`; они должны удаляться
сразу по завершении пайплайна, а не «когда-нибудь».
